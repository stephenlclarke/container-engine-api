# Pull request 45: bound Unix client requests and preserve executor progress

## Summary

- Admit native GET/POST recovery control only for the selected provider's explicit `engine.control.recovery` version 1 capability. Preserve normal API-version validation, private-session fingerprint and code-identity authentication. Do not alter the generated Docker route ledger or implement runtime cleanup in the gateway.
- Extend the existing native Bazel graph to the gateway and its dependencies, keeping socket fixtures in writable SSD test scratch. Reuse the reviewed standalone-copy workaround for incomplete rules_swift test bundles without weakening peer validation or re-signing cached binaries.
- Expose an optional successful response-head callback before body delivery so native clients can acknowledge a registered streaming wait before starting a container. Non-2xx responses never acknowledge readiness; callback failure aborts the request. This transport primitive does not itself make a provider's wait registration atomic.
- Add an additive raw duplex upgrade API for the Docker-free frontend's interactive exec/attach path. Serialize each direction on blocking dispatch workers, preserve header-adjacent bytes and stdin half-close, and duplicate descriptors under the ownership lock so concurrent close cannot operate on a reused descriptor.
- Add a monotonic request lifetime and cancellation/deadline shutdown while retaining descriptor close ownership in the blocking worker.
- Use nonblocking connect and bounded polling; execute blocking reads/writes on dispatch workers through a checked continuation instead of `Task.detached` on Swift's cooperative executor.
- Bound complete response heads, chunk framing lines and aggregate trailers; reject empty, signed, non-hexadecimal and overflowing chunk sizes.
- Add real-socket cancellation, trickle, malformed-input, path, response-mode and parallel-progress regressions.
- Add a focused native Bazel graph and Makefile target, reusing the checksum-locked family launcher and SSD test wrapper. This is not a whole-package Bazel migration.
- Defer hosted CI/Sonar while a PR is a draft and trigger both on `ready_for_review`; non-draft, main, release/manual authorities and Sonar trust checks remain unchanged. No hosted build is required to preserve this local development checkpoint.

See [problem and acceptance criteria](ISSUE-45.md) and [draft PR 45](https://github.com/stephenlclarke/container-engine-api/pull/45).

## Compatibility and remaining risk

`timeoutSeconds` now bounds the entire request rather than only idle system calls. Consumers with intentionally long-lived streams must choose a suitable larger finite deadline. Synchronous response callbacks must cooperate and must not block indefinitely. No existing Docker route, wire model or provider identity validation changes. The additive native recovery route is absent unless the selected provider explicitly advertises its supported capability version; the provider retains all recovery policy. Rare OS error paths and connect-poll branches are not all instrumented by the focused tests; they remain visible in the coverage denominator.

The new duplex API is strict about upgrade negotiation and leaves Docker multiplex decoding to the consumer. Its deadline interrupts both directions, including when a synchronous check observes expiry before the timer; callers still explicitly close the returned connection. This is transport capability, not proof that the devcontainer lifecycle frontend, production packaging or D01 candidate path is complete.

Package-wide tests, exact-head Sonar/sanitizers and runtime consumer qualification remain required at the coherent integration checkpoint. The devcontainer facade's interactive execution path is still being implemented. Do not merge or release this draft as a substitute for those checks. Close the topic branch and remove its isolated worktree after reviewed integration; retain its test evidence and any failed diagnostic trace.
